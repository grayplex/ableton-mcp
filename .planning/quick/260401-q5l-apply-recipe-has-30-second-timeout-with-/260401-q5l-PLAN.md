<objective>
Add progress feedback and scaled timeouts to apply_recipe so callers are not left waiting
in silence for up to 30 seconds during device loading.

Purpose: When apply_recipe loads multiple devices (e.g., EQ8 + Compressor + Reverb), Ableton
may stall scanning VST libraries. The MCP client sees no output until success or timeout.
This is confusing for AI agents that assume the server has hung.

Output: Async MCP tools that log device-loading intent via ctx.info(), scaled timeouts
proportional to device count, and actionable timeout error messages.
</objective>

  <action>
    1. Make `apply_mix_recipe` and `apply_master_recipe` async:
       ```python
       @mcp.tool()
       async def apply_mix_recipe(ctx: Context, track_index: int, role: str, genre: str) -> str:
       ```

    2. After computing `devices_payload` but before `send_command`, log intent via ctx.info():
       ```python
       device_names = [d["class_name"] for d in devices_payload]
       await ctx.info(
           f"Applying {role}/{genre} recipe: loading {len(device_names)} device(s) "
           f"[{', '.join(device_names)}]. This may take 10-30s if Ableton is scanning plugins."
       )
       ```

    3. Compute a scaled timeout: `timeout = max(30.0, len(devices_payload) * 15.0)`
       This gives 15s per device with a 30s floor. A 3-device recipe gets 45s, a 5-device
       recipe gets 75s. Pass this to send_command:
       ```python
       result = conn.send_command("apply_recipe", {
           "track_index": track_index,
           "track_type": "track",
           "devices": devices_payload,
       }, timeout=timeout)
       ```

    4. After send_command returns, run the blocking socket call in an executor so the
       async event loop stays responsive. Use `asyncio.get_event_loop().run_in_executor()`:
       ```python
       import asyncio
       loop = asyncio.get_event_loop()
       result = await loop.run_in_executor(None, lambda: conn.send_command("apply_recipe", {
           "track_index": track_index,
           "track_type": "track",
           "devices": devices_payload,
       }, timeout=timeout))
       ```
       This is important: making the tool async but calling send_command synchronously
       would block the event loop. run_in_executor offloads it to a thread.

    5. Apply the same pattern to `apply_master_recipe`.

    6. Do NOT change `get_mix_recipe`, `get_master_recipe_info`, `list_available_recipes`,
       or `set_sidechain_source` -- they are fast and don't need this.

    7. Add `import asyncio` at the top of the file.
