# Quick Task 260401-p84: has_devices means any device, not just instruments — Summary

**Date:** 2026-04-01
**Status:** Complete
**Commit:** 7aa9c9e

## What Was Done

Fixed a false-positive bug in `get_arrangement_state`: the `has_devices` field used `len(track.devices) > 0`, which returned `True` for FX-only tracks that have no instrument. Checkpoint logic, next_actions, and evaluation all used this flag as a proxy for "track has an instrument loaded", causing incorrect phase completion signals.

### Changes

**Remote Script (`AbletonMCP_Remote_Script/handlers/scaffold.py`)**
- Renamed field: `has_devices` → `has_instrument`
- Fixed logic: `len(track.devices) > 0` → `getattr(track, "has_audio_output", False)`
- `has_audio_output` is the Live API property that is `True` only when an instrument is present; FX-only MIDI tracks return `False`
- Updated docstring

**Consumers (pure rename, no logic change needed)**
- `MCP_Server/evaluation/arrangement.py`: `has_devices` → `has_instrument`
- `MCP_Server/orchestration/checkpoint.py`: 7 occurrences renamed
