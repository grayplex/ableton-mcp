# Milestone v1.4: Mix/Master Intelligence

**Status:** ✅ SHIPPED 2026-03-30
**Phases:** 29–34
**Total Plans:** 11

## Overview

Give Claude reliable mixing and mastering in Ableton by eliminating parameter guessing — role×genre recipes map principles to exact device values; analysis tools close the feedback loop.

## Phases

### Phase 29: Device Parameter Catalog and Role Taxonomy

**Goal**: Users can look up exact API parameter names, value ranges, and unit conversions for all target devices, and retrieve the canonical role taxonomy that organizes recipe lookup
**Depends on**: Phase 28 (v1.3 arrangement infrastructure)
**Requirements**: CATL-01, ROLE-01
**Plans**: 2 plans

Plans:
- [x] 29-01-PLAN.md — Devices package, catalog data, MCP tools, and tests
- [x] 29-02-PLAN.md — Bootstrap script and live Ableton catalog verification

**Details:**
- `MCP_Server/devices/catalog.py` — static CATALOG dict (12 devices, 327 parameters from live Ableton session)
- `MCP_Server/devices/__init__.py` — `get_catalog_entry()` and `get_roles()` public API
- `MCP_Server/tools/catalog.py` — `get_device_catalog` and `get_role_taxonomy` MCP tools
- Bootstrap script (`scripts/bootstrap_catalog.py`) queries live Ableton session to generate catalog; class name corrections (Compressor2, AutoFilter2, MxDeviceAudioEffect, StereoGain) confirm live data used

**Depends on**: Phase 29
**Requirements**: RECIP-01
**Plans**: 2 plans

Plans:
- [x] 30-01-PLAN.md — Mixing package infrastructure, tests, house and techno recipes
- [x] 30-02-PLAN.md — Ambient and DnB recipes, get_mix_recipe MCP tool

**Details:**

### Phase 31: Apply Recipe and Batch Parameter Tools

**Goal**: Users can apply a track mix recipe or master bus recipe to an Ableton track in one MCP call with atomic device loading, and set multiple parameters in a single socket round-trip
**Depends on**: Phase 30
**Requirements**: BATCH-01, APPLY-01, APPLY-02, APPLY-03, SIDE-01
**Plans**: 2 plans

Plans:
- [x] 31-01-PLAN.md — Conversion module, master recipe data, and tests
- [x] 31-02-PLAN.md — RS handlers, MCP tools, and integration tests

**Details:**
- `MCP_Server/devices/convert.py` — `natural_to_normalized()` and `convert_recipe_to_payload()`; handles log, linear, linear_db conversions
- `MASTER_RECIPE` constants for house, techno, ambient, drum_and_bass (GlueCompressor + MultibandDynamics + Limiter)
- `apply_recipe` RS handler with `self_scheduling=True` + response queue — recursive load-verify pattern guarantees atomicity

- `set_sidechain_source` RS handler — case-insensitive substring match on routing display names
- `apply_mix_recipe`, `apply_master_recipe`, `set_sidechain_source` MCP tools
- `DEVICE_PATHS` dict maps 12 class names to browser paths for device loading

## Milestone Summary

**Key Decisions:**
- Device catalog MUST be bootstrapped from live Ableton queries, not hand-authored from docs (CATL-01 constraint)
- Spectrum analysis and LUFS metering dropped — architecturally impossible via LOM (Spectrum device exposes no frequency bin data; LUFS requires raw audio buffer access)
- Sidechain routing full automation deferred to v1.5; basic sidechain source setting in v1.4
- mixing/ package as peer to genres/ and theory/ — never modifies genre blueprints
- apply_recipe RS handler uses self_scheduling=True + response_queue for atomic device loading
- Normalization contract: convert_recipe_to_payload() produces 0..1 normalized values; RS handlers clamp to 0..1 (not raw p.min/p.max)

**Issues Resolved:**
- Phase 32 gap: `analysis` module missing from `tools/__init__.py` — tools were invisible to MCP clients; fixed in 32-02 re-verification
- Phase 34 AutoFilter2 class name mismatch (AutoFilter vs AutoFilter2) — caught and fixed during execution
- APPLY-02/MSTR-01 normalization bug: RS clamp used raw device ranges instead of 0..1; fixed post-audit

**Issues Deferred:**
- Full sidechain chain automation (auto-wire all genre-conventional sidechain connections) — v1.5+
- Section-aware mixing (different settings per arrangement section) — requires automation infrastructure, v1.5+
- Frequency conflict detection — requires audio analysis beyond LOM meter access, v1.5+
- Nyquist VALIDATION.md execution for phases 29-34 — strategy drafts exist but not executed

**Technical Debt:**
- CATL-01 live Ableton spot-check still a pending human verification (bootstrap ran with 327 params, class name corrections confirm live data)
- 290 pre-existing async mock failures in test suite unrelated to v1.4
- VALIDATION.md files exist as drafts for all 6 phases; Nyquist validation not executed
