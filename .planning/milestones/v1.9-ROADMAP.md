# Milestone v1.9: Orchestration/Agent Loop

**Status:** ✅ SHIPPED 2026-04-01
**Phases:** 48-51
**Total Plans:** 4

## Overview

Give Claude a methodical execution layer for full productions — an agenda of named phases, a concrete tool-call checklist per phase, a checkpoint that reads live Ableton state to determine exactly where the production is, and a next-actions recommender that returns specific ordered tool calls so Claude spends no context budget on "what should I do?" reasoning.

### Phase 50: Production Checkpoint System

**Goal**: Claude can call `get_production_checkpoint` at any moment during a production to get a compact, accurate summary of what phases are complete, what is active, and a single-sentence resume hint
**Depends on**: Phase 48
**Requirements**: CHKP-01, CHKP-02
**Plans**: 1 plan

Plans:

- [x] 50-01: Production Checkpoint System

**Details:**
- `MCP_Server/orchestration/checkpoint.py`: RS-based phase inference from live session topology
- Phase completion heuristics: setup (tracks exist), drums (Drum Rack + clips), bass (bass-named track + clips), harmony (chord/pad track + ≥4-note clips), mix (EQ Eight + Compressor present), master (GlueCompressor + Limiter on master)
- Master short-circuit: GlueCompressor + Limiter2 on master → all phases complete (avoids requiring sound_design devices)
- Empty session returns clear `resume_hint`: "Session is empty — start with setup: tempo, key, and scaffold tracks"
- `resume_hint` always a single human-readable sentence naming the specific next action
- Serializes to ≤300 tokens JSON
- 5 tasks completed, 4 files changed

### Phase 51: Next-Action Recommender and Phase Transition Gate

**Goal**: Claude can call `get_next_actions` to receive the next N specific, immediately-executable tool calls — and `get_phase_transition_guidance` to get a go/no-go verdict before advancing phases
**Depends on**: Phase 49, Phase 50
**Requirements**: NEXT-01, NEXT-02
**Plans**: 1 plan

Plans:

- [x] 51-01: Next-Action Recommender and Phase Transition Gate

**Details:**
- `MCP_Server/orchestration/next_actions.py`: reads checkpoint → determines active phase → returns next N ExecutionStep entries
- Explicit `phase_name` bypasses checkpoint (pure computation, no Ableton connection needed)
- `n` parameter: default 10, max 25; `get_next_actions("techno", n=5)` returns exactly 5 steps
- Steps already inferred-complete skipped (kick present → skip add-kick step)
- `get_phase_transition_guidance(from_phase, genre, to_phase?)`: per-phase completion checks with specific blockers and fix hints; reuses evaluator internals for mix phase
- Fallback to setup checklist on connection error
- All 5 tools registered: `get_production_agenda`, `get_phase_execution_plan`, `get_production_checkpoint`, `get_next_actions`, `get_phase_transition_guidance`

## Milestone Summary

**Key Decisions:**

- Orchestration is advisory — tools return checklists and next steps; Claude executes; no autonomous loop in server
- Checkpoint reads live Ableton state (not persisted) — phase completion inferred heuristically from session topology
- ExecutionStep uses sentinel values for session-state args — Claude resolves at call time; keeps checklist generation stateless
- Token budget enforced by compact note arrays (≤8 notes per step) and short descriptions; all checklists <2000 chars
- Master phase short-circuits phase-walk — GlueCompressor+Limiter2 on master → all phases complete
- `get_next_actions` with explicit `phase_name` bypasses Ableton connection (pure computation)

**Issues Resolved:**

- None significant — clean implementation across 4 phases

**Issues Deferred:**

- HIST-01: `append_execution_log` session-scoped step history — deferred post-v1.9
- PARA-01: Parallel phase execution with `can_parallelize` flag — sequential model first
- ADPT-01: `refine_agenda(agenda, feedback)` — deferred post-v1.9

**Technical Debt Incurred:**

- Phase completion heuristics are approximate (topology-based); no ground-truth execution log
- `active_phase_progress` is estimated, not exact
