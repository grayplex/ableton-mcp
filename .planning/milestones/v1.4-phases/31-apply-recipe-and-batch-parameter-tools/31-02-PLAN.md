```python
@command("apply_recipe", write=True, self_scheduling=True)
def _apply_recipe(self, params):
    """Atomically load missing devices and set all parameters.

    Params:
        track_index: int (ignored if track_type="master")
        track_type: "track" | "return" | "master"
        devices: list of {"class_name": str, "params": {param_name: normalized_value}}
    """
```

Logic (follows load_browser_item pattern):
1. Extract `track_index`, `track_type`, `devices_spec` from params
2. Resolve track via `_resolve_track(self._song, track_type, track_index)`
3. Build `existing` dict: `{device.class_name: device}` for first match of each class (per D-04, D-05)
4. Split devices_spec into `to_load` (missing) and `to_update` (existing)
5. Create `response_queue = queue.Queue()`
6. If nothing to load: set all params immediately (no async needed), put result in queue
7. If devices to load: use `schedule_message` pattern:
   - For each device to load, get browser path from `DEVICE_PATHS[class_name]`
   - Use `self._resolve_browser_path(app.browser, path)` from BrowserHandlers (the class has access via MRO) to get the browser item
   - Call `self._song.view.selected_track = track` then `app.browser.load_item(item)` in a scheduled callback
   - Schedule verification callback that checks `len(track.devices)` increased
   - After all devices loaded, set all params (both for newly loaded and existing devices)
   - Put result in response_queue

IMPORTANT: The `apply_recipe` handler needs to load devices sequentially (one at a time), waiting for each to confirm before loading the next. After ALL devices are loaded, set ALL params. Use a recursive scheduling approach:

```python
def _load_next_device(self, track, to_load, load_index, all_specs, existing, response_queue):
    """Load the next device in the queue, or set params if all loaded."""
    if load_index >= len(to_load):
        # All loaded -- now set params for ALL specs
        self._apply_all_params(track, all_specs, existing, response_queue)
        return
    # ... load next device, schedule verify, then _load_next_device for next
```

8. Block on `response_queue.get(timeout=30.0)` and return result

Add `apply_mix_recipe` tool (per D-01, D-03):

```python
@mcp.tool()
def apply_mix_recipe(ctx: Context, track_index: int, role: str, genre: str) -> str:
    """Apply a mix recipe to a track: loads required devices and sets all parameters.

    Looks up the role x genre recipe, converts natural-unit values to normalized,
    sends a single apply_recipe command to load missing devices and set all params atomically.

    Parameters:
    - track_index: Index of the track to apply the recipe to
    - role: Mixing role (kick, bass, lead, pad, chords, vocal, atmospheric, return)
    - genre: Genre (house, techno, ambient, dnb/drum_and_bass)
    """
    recipe = get_recipe(role, genre)
    if recipe is None:
        return format_error(
            f"No recipe found for role='{role}', genre='{genre}'",
            suggestion="Roles: kick, bass, lead, pad, chords, vocal, atmospheric, return, master. "
                       "Genres: house, techno, ambient, dnb",
        )

    devices_payload = convert_recipe_to_payload(recipe)

    conn = get_ableton_connection()
    result = conn.send_command("apply_recipe", {
        "track_index": track_index,
        "track_type": "track",
        "devices": devices_payload,
    })
    return json.dumps(result, indent=2)
```

```python
@mcp.tool()
def set_sidechain_source(ctx: Context, track_index: int, device_index: int, source_track_name: str, track_type: str = "track") -> str:

    Resolves the source track name to the correct routing at apply time.

        "device_index": device_index,
        "track_type": track_type,
        "source_track_name": source_track_name,
    })
    return json.dumps(result, indent=2)
```
