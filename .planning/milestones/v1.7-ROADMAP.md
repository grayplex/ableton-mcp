# Milestone v1.7: Prompt Interpretation

**Status:** ✅ SHIPPED 2026-03-31
**Phases:** 42-44
**Total Plans:** 3

> **Note:** Phase planning directories (42, 43, 44) were not created for this milestone — all three phases were implemented as a single monolithic commit (`478a1a5`) covering the full v1.7 scope.

## Overview

Formalize Claude's natural-language music prompt reasoning into a structured, repeatable planning step — so "lo-fi hip hop beat" consistently yields the same quality of concrete parameters (tempo, scale, groove, instruments, effects) as careful ad-hoc reasoning, every time.

## Phases

### Phase 42: ProductionBrief Schema, Signal Lexicon, and Prompt Parser

**Goal**: The foundation layer exists — a validated `ProductionBrief` TypedDict schema, a signal lexicon covering all 12 genres and common descriptors, and a tokenizer that classifies free-text tokens into five signal types; no derivation logic yet, just extraction and schema
**Depends on**: Nothing (first phase of v1.7)
**Requirements**: PARS-01, LEX-01, BRIEF-01
**Plans**: 1 plan (implemented in single commit)

**Details:**
- `MCP_Server/prompt/schema.py`: `SignalSet` + `ProductionBrief` TypedDicts — 11 fields, JSON-serializable without `.asdict()`, nullable `primary_genre`
- `MCP_Server/prompt/lexicon.py`: 12-genre map with all blueprint aliases, 40+ mood adjectives (energy_level + scale_bias), 20+ instrument refs (role + descriptor), 20+ effect refs, 12+ tempo signals, groove hint overrides
- `MCP_Server/prompt/parser.py`: Greedy longest-match tokenizer — multi-word phrases first (`lo_fi_hip_hop` before `hip_hop`), stop words preserved for phrase matching ("drum and bass"), 5-level priority: genre > instrument > effect > mood > tempo
- `tests/test_prompt_phase42.py`: 275 tests covering multi-word alias matching, mixed-case, unknown tokens → raw_descriptors, empty prompt → empty SignalSet with confidence 0.0

### Phase 43: Parameter Derivation Engine

**Goal**: The derivation engine translates a `SignalSet` into a fully-populated `ProductionBrief` — all five DERV-* requirements implemented with deterministic rules and each derivation step appends a reasoning note
**Depends on**: Phase 42
**Requirements**: DERV-01, DERV-02, DERV-03, DERV-04, DERV-05
**Plans**: 1 plan (implemented in single commit)

**Details:**
- `MCP_Server/prompt/deriver.py`: 5 derivation steps — explicit BPM extraction (±5 window), genre + energy modifier tempo, genre + mood scale_bias key feel, genre + structural hint groove override, blueprint role instrument hint merge; reasoning list appended at every step
- Tempo: explicit BPM → ±5 range; else genre BPM range + energy modifier (±10% per point from 5); clamped 40-200 BPM
- Key feel: genre convention → mood override (euphoric/uplifting → major, dark/melancholic → minor/phrygian)
- Groove: genre default (lo-fi → boom_bap 65% swing, house → four_on_floor 0-5%, DnB → breakbeat 15%) → structural hint override
- `tests/test_prompt_deriver.py`: 261 tests

**Goal**: Claude can call `interpret_prompt` to get a structured `ProductionBrief` from any music description, and call `interpret_prompt_to_plan` to go straight from text to a full production plan in one tool call
**Depends on**: Phase 43

## Milestone Summary

**Key Decisions:**

- Parser is deterministic rule-based (not LLM) — Claude provides NLP, parser provides structure
- Greedy longest-match tokenizer: multi-word phrases matched first to handle aliases like "lo fi hip hop"
- 5-level priority (genre > instrument > effect > mood > tempo) — genre always wins in ambiguous cases
- `ProductionBrief` is JSON-serializable without `.asdict()` — TypedDict approach consistent with codebase
- `interpret_prompt_to_plan` chains directly to `generate_production_plan` — no intermediate steps needed
- All computation server-side; no Remote Script changes needed

**Issues Resolved:**

- None significant — clean implementation in single pass
