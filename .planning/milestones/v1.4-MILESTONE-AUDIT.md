## Critical Gaps

### P0: Normalization Bug — apply_master_recipe / set_device_parameters

**Files:** `AbletonMCP_Remote_Script/handlers/devices.py` lines 2438 and 2726

**Root cause:** `convert_recipe_to_payload()` (MCP side) outputs normalized 0..1 values. The RS handler `_apply_all_params` clamps with `max(p.min, min(p.max, float(value)))` using the *raw device range* — not 0..1. For parameters with raw ranges outside 0..1, the value lands at the wrong position:

| Device | Parameter | Raw Range | Example: recipe intends | Sets to | Actual dB |
|--------|-----------|-----------|------------------------|---------|-----------|
| GlueCompressor | Makeup | 0..20 | +2 dB → 0.567 normalized | 0.567/20 range | ~-14 dB |
| GlueCompressor | Range | 0..70 | medium → ~0.5 normalized | 0.5/70 range | near minimum |
| MultibandDynamics | Master Output | -24..24 | 0 dB → 0.5 normalized | 0.5 on -24..24 | -12 dB |
| MultibandDynamics | Output Gain (x3) | -24..24 | varies | wrong | wrong |

**Affected:** APPLY-02, MSTR-01, and BATCH-01 when sending normalized values.
**Not affected:** APPLY-01 per-track recipes (Eq8, Compressor2, Reverb, Delay, Gate, StereoGain, DrumBuss all use 0..1 raw ranges).

**Fix:** Change both clamp calls to `max(0.0, min(1.0, float(value)))` — the RS contract is that recipe payloads are pre-normalized 0..1 by the MCP layer.

---

### P1: AutoFilter2 LFO Rate vs LFO Freq in Phase 34 Recipes

**Files:** `MCP_Server/mixing/synthwave.py`, `dubstep.py`, `trance.py`, `future_bass.py`, `lo_fi.py`, `hip_hop_trap.py` (7 occurrences across 6 files)

**Root cause:** CATALOG `"LFO Rate"` (index 17, raw 0..21) is a tempo-synced beat parameter. Recipe authors intended slow free-running LFO modulation — which requires `"LFO Freq"` (index 15, 0..1) or `"LFO Time"` (index 16, 0..1). Setting `LFO Rate = 0.2` on a 0..21 beat scale produces near-minimum tempo sync, not subtle filter movement.

**Affected:** RECIP-02 (recipe data quality), APPLY-01 for these genres' pad/atmospheric roles.

**Fix:** Replace `"LFO Rate"` with `"LFO Freq"` in the 6 affected recipe files. Values like 0.2–0.3 are reasonable for `"LFO Freq"` (slow free-running modulation).

## Summary

Two real bugs found by cross-phase integration analysis:

1. **P0 (blocking):** RS `_apply_all_params` uses raw device parameter ranges for clamping normalized 0..1 values. GlueCompressor and MultibandDynamics master chain params will be set to wrong values. APPLY-02 and MSTR-01 are functionally broken at the sonic level.

2. **P1 (data quality):** 6 Phase 34 genre files use AutoFilter2 `"LFO Rate"` (tempo-synced) when `"LFO Freq"` (free-running) was intended. LFO modulation will be inaudible in these genres.

Both are fixable with minimal code/data changes. Recommend creating a gap-closure phase before completing the milestone.
