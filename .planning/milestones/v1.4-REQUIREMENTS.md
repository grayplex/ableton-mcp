## Milestone v1.4 Requirements

### Foundation

- [x] **CATL-01**: User can look up exact Ableton API parameter names, value ranges, and normalized-to-natural-unit conversion formulas for EQ Eight, Compressor, Glue Compressor, Drum Buss, Multiband Dynamics, Reverb, Delay, Auto Filter, Gate, Limiter, Envelope Follower, and Utility — catalog bootstrapped from live Ableton queries, not documentation
  - _Outcome: Validated. 327 parameters across 12 devices from live Ableton session. Phase 29._
- [x] **ROLE-01**: User can retrieve the canonical mixing role taxonomy — the role identifiers (kick, bass, lead, pad, chords, vocal, atmospheric, return, master) used as keys for recipe lookup across all genres
  - _Outcome: Validated. 9 roles. Phase 29._
- [x] **BATCH-01**: User can set multiple device parameters in a single socket call via a Remote Script batch handler — reducing recipe application from N sequential round-trips to one
  - _Outcome: Validated. set_device_parameters RS command. Phase 31._

### Mix Recipes

- [x] **RECIP-01**: User can retrieve a role×genre mix recipe for any of the 4 core genres (house, techno, ambient, DnB) — returns EQ, compression, reverb/delay, panning, and dynamics parameter values for the specified role
  - _Outcome: Validated. Phase 30._
- [x] **RECIP-02**: User can retrieve a role×genre mix recipe for all 12 genres — extends RECIP-01 to synthwave, hip-hop/trap, dubstep, trance, lo-fi, future bass, disco/funk, and neo-soul/R&B
  - _Outcome: Validated. 8 new genre files. Phase 34._
- [x] **MSTR-01**: User can retrieve a master bus recipe for any of the 12 genres — returns parameter settings for a Glue Compressor + Multiband Dynamics + Limiter chain appropriate to that genre's loudness and tonal conventions
  - _Outcome: Validated. Phase 34._

### Apply Tools

- [x] **APPLY-01**: User can apply a role×genre mix recipe to an Ableton track in one MCP tool call — loads the required devices and sets all parameters without requiring multiple sequential tool calls from Claude
  - _Outcome: Validated. apply_mix_recipe MCP tool. Phase 31._
- [x] **APPLY-02**: User can apply a genre master bus recipe to the Ableton master track in one MCP tool call
  - _Outcome: Validated (after post-audit fix: RS normalization bug corrected). Phase 31._
- [x] **APPLY-03**: Recipe application is atomic with respect to device loading — parameters are set only after the device is confirmed as instantiated in the Ableton session (no race condition on async device load)
  - _Outcome: Validated. self_scheduling=True + response_queue pattern. Phase 31._

### State Analysis

- [x] **STATE-01**: User can retrieve current device parameters for every device on every track in a single MCP tool call — returns a complete snapshot of the session's mix state without N sequential reads
  - _Outcome: Validated. get_mix_state RS + MCP tool. Phase 32._
- [x] **GAIN-01**: User can run a gain staging check — returns per-track dBFS estimates from track meter levels, compares to role-based targets, and flags tracks significantly above or below target
  - _Outcome: Validated. check_gain_staging MCP tool. Phase 32._
- [x] **GAIN-02**: Gain staging check excludes MIDI tracks with no instrument loaded from analysis — no false-positive flags on empty scaffold tracks
  - _Outcome: Validated. MIDI guard in get_track_meters RS handler. Phase 32._

### Mix Intelligence

- [x] **INTEL-01**: User can request mix adjustment suggestions for a track — returns a list of parameter diffs (current value → suggested value) with a one-sentence reason per change, based on comparing current device state against the role×genre recipe
  - _Outcome: Validated. suggest_mix_adjustments MCP tool. Phase 33._

### Sidechain Routing

- [x] **SIDE-01**: User can set a compressor's sidechain input source by track name — resolves the source track to the correct index at apply time rather than requiring hardcoded track indices
  - _Outcome: Validated. set_sidechain_source RS + MCP tool. Phase 31._

## Requirements Not Pursued (Dropped / Out of Scope)

- **Spectrum frequency analysis** — Ableton's Spectrum device exposes no frequency bin data via the LOM; dropped from v1.4
- **LUFS metering** — Requires raw audio sample arrays; MCP Server and Remote Script have no audio buffer access; dropped from v1.4
- **Automated mixing without human confirmation** — suggest_mix_adjustments always returns diffs for review; design decision, not a gap

## Future Requirements (Deferred to v1.5+)

- Section-aware mixing — apply different mix settings per arrangement section
- Frequency conflict detection — detect masking between competing tracks
- Full sidechain chain automation — auto-wire all genre-conventional sidechain connections in one call
