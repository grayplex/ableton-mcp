# Milestone v1.8: Iterative Refinement Protocol

**Status:** ✅ SHIPPED 2026-03-31
**Phases:** 45-47
**Total Plans:** 3

## Overview

Give Claude the ability to take a follow-up instruction like "make the bridge darker" and act on it correctly — reading back the current section state, interpreting the aesthetic instruction in context (darker: lower register, minor substitutions, filter highs, heavier compression), and surgically modifying just that section's notes and devices without touching anything outside it.

## Phases

### Phase 45: Section State Reader

**Goal**: Claude can read back everything it already built in a named arrangement section — clips, notes, devices, and mix context — in a single structured snapshot; no refinement logic yet, just a reliable read
**Depends on**: Nothing (first phase of v1.8)
**Requirements**: SNAP-01, SNAP-02
**Plans**: 1 plan

Plans:

- [x] 45-01: Section State Reader — get_section_state MCP tool + get_arrangement_clip_notes RS command

**Details:**
- New RS command `get_arrangement_clip_notes` in `handlers/arrangement.py` — finds clip by start_time (±0.01 beat), returns note list; needed because `get_notes` uses session-view `clip_slots`, not arrangement_clips
- `MCP_Server/refinement/schema.py`: `ClipSummary`, `TrackStateEntry`, `SectionState` TypedDicts — JSON-serializable
- `get_section_state(section_name, genre=None)` MCP tool: resolves locator range → collects clips per track → note summaries (pitch_min/max, dominant_octave, rhythm_density) + mix_context (device params + optional recipe_delta)
- Tracks with zero clips in section range omitted entirely (D-09)
- Recipe delta threshold: 20% (coarser than suggest_mix_adjustments' 3% — read-only snapshot)
- 11 tests passing

### Phase 46: Refinement Language Engine

**Goal**: Claude can interpret "make the bridge darker" or "add more swing" into a concrete `SectionRefinementPlan` — specific note operations and device parameter targets per track — and update an existing `ProductionBrief` via follow-up refinement text
**Depends on**: Phase 45
**Requirements**: REFN-01, REFN-02, PARS-02
**Plans**: 1 plan

Plans:

- [x] 46-01: Refinement Language Engine — lexicon, interpreter, refine_prompt

**Details:**
- `MCP_Server/refinement/lexicon.py`: `RefinementVector` TypedDict with `HarmonicDelta`, `TimbralDelta`, `DynamicDelta` sub-types; `REFINEMENT_LEXICON` with 22 adjectives (darker, brighter, warmer, colder, harder, softer, heavier, lighter, sparser, denser, higher, lower, more_energetic, less_energetic, more_melodic, more_rhythmic, more_spacious, tighter, dirtier, cleaner, more_dark, more_bright)
- `MCP_Server/refinement/interpreter.py`: tokenizes instruction → matches lexicon → builds per-track `SectionRefinementPlan`; avoids importing from `MCP_Server.tools` to prevent circular imports
- `interpret_section_refinement(section_name, instruction)` MCP tool — read-only plan
- `refine_prompt(brief, refinement_text)` MCP tool — partial re-derivation with diff output; detects explicit BPM via regex in addition to classify_prompt tempo_signals

### Phase 47: Refinement Application Tools

**Goal**: Claude can execute a refinement end-to-end — "make the bridge darker" applies the note and device changes to only the Bridge section and returns a plain-English summary of exactly what changed
**Depends on**: Phase 46
**Requirements**: RFNA-01, RFNA-02, RFNA-03
**Plans**: 1 plan

Plans:

- [x] 47-01: Refinement Application — apply_section_note_refinement, apply_section_device_refinement, refine_section

**Details:**
- New RS commands: `transpose_arrangement_clip` and `modify_arrangement_clip_notes` in `handlers/arrangement.py` — handle arrangement-view note editing that session-view commands can't reach
- `apply_section_note_refinement(section_name, track_name, semitone_shift, density_delta, scale_substitutions)` — transposes notes in section bar range only; clips outside range untouched
- `apply_section_device_refinement(section_name, track_name, param_targets, write_automation)` — device param changes with automation guidance
- `refine_section(section_name, instruction, genre)` — end-to-end: interpret → apply → return tracks_modified, note_changes, device_changes, reasoning

## Milestone Summary

**Key Decisions:**

- New RS commands required for arrangement-view note editing (`transpose_arrangement_clip`, `modify_arrangement_clip_notes`) — existing session-view commands use `clip_slots` not `arrangement_clips`
- `interpreter.py` avoids importing from `MCP_Server.tools` to prevent circular imports; uses inline beat-to-bar logic
- `refine_prompt` detects explicit BPM via regex in addition to classify_prompt tempo_signals
- Recipe delta threshold 20% for section state snapshots (vs 3% in suggest_mix_adjustments) — coarser threshold appropriate for read-only context
- Tracks with zero clips in section range omitted entirely from SectionState (cleaner output)

**Issues Resolved:**

- Session-view vs arrangement-view API gap: needed new RS commands for arrangement-view note editing

**Issues Deferred:**

- None

**Technical Debt Incurred:**

- Phase 47 SUMMARY.md was never created
- `apply_section_device_refinement` writes automation guidance note rather than true automation breakpoints (full breakpoint interpolation deferred)
